The Situation

The Factbook was previously built through undocumented methods left by a prior assistant director, using a fully manual Excel template rebuilt from scratch every semester. Processing enrollment, program, and demographic data meant re-entering and re-checking everything by hand each term — nothing was reusable, and key data sources were siloed and had never been integrated.

OPEIR's Director and technical liaison brought me in to rebuild this into something a non-technical analyst could actually own and run themselves.

What I Built — Three Attempts to Get the Right Fit

My first instinct was Alteryx: build the ETL logic properly, once, instead of rebuilding an Excel template every semester. It worked technically, but it created a new problem — Alteryx workflows were hard to build and, more importantly, hard for non-technical staff to adjust when reporting definitions changed term to term. A tool only the builder can maintain isn't actually a fix.

Second attempt was Jupyter Notebooks — more flexible, but this reintroduced the same core problem from a different angle: it still required someone comfortable editing code, and non-technical staff hit real friction trying to run it (including PATH configuration errors just to execute Python from the command line).

The third attempt — Streamlit — is what actually worked. Two web apps, "ENR Merger" and "Enrollment Pipeline," packaged with one-click batch files, gave non-technical staff a real interface: no code, no terminal, just a button. The underlying pipeline still used Alteryx for ETL (enrollment classification, demographics, residency, minors, athletics, program migration) and Power BI with custom DAX for the dashboard suite — Streamlit was the missing front door that made the rest of the system actually usable by the person who'd own it day to day.

The Enrollment by Classification workflow was validated directly against official university totals before anything else was built on top of it — establishing trust in the foundation layer first.

Errors Caught Before Publication

Honors College headcount

A many-to-many join was inflating the count

A join bug was duplicating Honors College students in the output. Fixed via a Join → Unique → Union pattern, correcting the figure to the true count of 334 students.

Pell-eligibility reporting

Published numbers reflected the wrong metric entirely

The Factbook had been reporting awarded Pell grants where it should have reported eligible students. Corrected to 4,028 — confirmed directly by the technical liaison: "4,028 is correct and what should be shown."

Residency reporting

A 139-student discrepancy traced to county-code mapping

Diagnosed by mapping FIPS county codes 155–189, reconciling the total to match the official published figure of 11,636.

Online enrollment

Students were being counted more than once

Diagnosed and fixed an overcount via de-duplication on term and student ID plus modality filters, then rebuilt a bloated 13-page output into 3 clean matrices after stakeholder feedback.

Honest Limitations

  • No hard "before" time baseline exists for the legacy manual process — it was never timed. The efficiency story rests on error-reduction and accessibility evidence (non-technical staff literally couldn't run the old system), not an invented hours-saved percentage. The ~40% development-time reduction from reusable Alteryx macro patterns is a self-estimate, not a measured figure.
  • ~20 minor programs still needed manual department/faculty mapping at handoff — the crosswalk wasn't fully complete.
  • Some historical data (2009/2010 graduation cohorts, older degree records) had to be manually copied from prior published Factbooks rather than being pipeline-generated — a gap in true end-to-end automation.
